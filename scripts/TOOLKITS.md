# Paid toolkits on savingoptimizer.com

Generated by `python3 scripts/build-toolkits.py` (idempotent; re-run after any config change).

| Path | What | Indexed |
|---|---|---|
| `/toolkits/` (`toolkits/index.html`) | Hub of all 16 toolkits | yes, in sitemap |
| `/toolkits/<slug>.html` | One sales page per toolkit, priced CTA "Buy, CA$15" → Stripe Payment Link, no ad code | yes, in sitemap |
| `/toolkits/thank-you.php?sku=<slug>` | Download page after Stripe checkout | **noindex, nofollow** (meta + X-Robots-Tag), not in sitemap |
| `/toolkits/stripe-webhook.php` | Stripe webhook: emails the buyer their links (hand-written, not generated) | POST only, noindex |
| `toolkits/lib/` | `toolkit-data.php` (generated: names, bundle, Drive links, Payment Link IDs) and `webhook-core.php` (hand-written) | `.htaccess` denies all web access |

## Config (`scripts/toolkits-config.json`)
- `payment_links`: one live Stripe Payment Link per slug (created 2026-11-11; product metadata `brand=savingoptimizer`, `sku=<slug>`; CA$15.00 one-time). Drive sharing is Anyone with the link · Viewer (verified logged-out 2026-11-11).
- `bundles`: one bundle, `bundle-all` (all 16 for CA$39, live Stripe link). Shown as a panel at the top of `/toolkits/` and as a secondary "Get all 16 for CA$39" button on every sales page. `thank-you.php?sku=bundle-all` shows the bundle folder and zip and then each toolkit's own folder and zip.
- `hubs` / `top_posts`: where the priced CTA box goes (top posts = top 2 per toolkit from GSC 2026-08-01..11-03, clicks then impressions). UTMs: `utm_source=savingoptimizer&utm_medium=site&utm_campaign=toolkit&utm_content=hub-<hub>|post-<slug>`.
- `lead_magnet`: provider **Hostinger Reach** (the same provider latestmortgagerates.ca uses, as an embedded form). The sign-up block renders **hidden**, and the Reach script isn't emitted, until `reach_form_id` **and** `sender_mailing_address` (CASL) are both set. Set up in Reach first: verify savingoptimizer.com as a sending domain, turn on double opt-in, create an embedded form with email, optional first name and an **unticked** consent checkbox using the wording in `build-toolkits.py` (`signup()`), then add a welcome automation that sends the free sample. `privacy.html` switches to its newsletter wording automatically when the block is ready (the `tk-privacy:*` markers). If the site ever sends a Content-Security-Policy, allow `cdn-reach.hostinger.com`, `reach-forms.hostingerusercontent.com` and `reach.hostinger.com` (see the latestmortgagerates `.htaccess`).

## Buyer download links (in the repo, by decision)
`downloads` in the config holds each slug's (and `bundle-all`'s) Google Drive `folder_url` and `zip_url`. Andrew decided on 2026-11-11 that these links can be public in the repo. The build writes them into `toolkits/lib/toolkit-data.php`, which both the thank-you page and the webhook read, and it fails if any SKU is missing a link. There is no host-side INI or env setup any more (`.so-toolkit-links.ini` is no longer read). `payment_link_ids` maps each live Payment Link ID to its slug for the webhook.

## Delivery flow
1. The buyer pays on a Stripe Payment Link. The text under the pay button says: "After you pay, you'll go straight to your download page…".
2. Stripe redirects to `https://savingoptimizer.com/toolkits/thank-you.php?sku=<slug>&session_id={CHECKOUT_SESSION_ID}`, which shows the links right away. All 17 links use the redirect, not a hosted confirmation, because Stripe allows only one after-payment type and the page can show 34 bundle links, buttons and the Start Here tip.
3. At the same time Stripe sends `checkout.session.completed` to `https://savingoptimizer.com/toolkits/stripe-webhook.php` (live endpoint `we_1UaYZCFtabtGqOsdMFg2hbXS`, that event only). The webhook:
   - verifies `Stripe-Signature` (HMAC-SHA256 over `<t>.<raw body>`, every `v1` checked with `hash_equals`, 300-second tolerance);
   - acts only on Saving Optimizer purchases: `session.payment_link` in `payment_link_ids`, or metadata `brand=savingoptimizer` plus a known `sku`. Every other brand on the shared Stripe account gets a 200 and is ignored, and so are unpaid sessions and other event types;
   - is idempotent: an atomic `fopen(..., 'x')` claim file per Checkout Session in `.so-webhook-data/sent/`. A retry or duplicate gets a 200 and no second email;
   - emails `customer_details.email` an HTML + text message from contact@savingoptimizer.com with the links, the Start Here tip, the thank-you page link, the 30-day refund line and the free-updates line (both from `offer-brief.md`), then sends a short sale notice to contact@savingoptimizer.com;
   - if the buyer email fails, releases the claim and returns 500, so Stripe retries (for up to 3 days in live mode). A missing config also returns 500, so events that arrive before setup are delivered once the config is in place.
4. Mail transport: SMTP `smtp.hostinger.com:465` (SSL) as contact@savingoptimizer.com when the mailbox password is in the config (recommended: authenticated, DKIM-signed, inbox-friendly). Otherwise PHP `mail()` with `-f contact@savingoptimizer.com`. Hostinger only accepts a From that is a real mailbox on the domain. savingoptimizer.com already has Hostinger MX, SPF (`include:_spf.mail.hostinger.com`) and DKIM.

## Webhook config (secret, never in git)
`toolkits/stripe-webhook.php` loads a PHP file that returns an array (format: `scripts/so-webhook-config.sample.php`), from the first of:
1. the path in env `SO_WEBHOOK_CONFIG`;
2. **`<parent of the document root>/.so-webhook-config.php`**, recommended, e.g. `/home/<user>/domains/savingoptimizer.com/.so-webhook-config.php`. Git deploys never touch it;
3. `toolkits/lib/so-webhook-config.php`, a fallback only (web access is denied by `lib/.htaccess`, and it's gitignored, but a Git deploy could remove it).

Keys: `stripe_webhook_secret` (required), `smtp.pass` (contact@ mailbox password, optional), and optional `from_email`, `notify_email`, `transport`, `data_dir` and `tolerance`. State and a one-line-per-event log (`webhook.log`) go to `.so-webhook-data/` next to the config file. Permissions: config 600, data dir 700.

## Test
`PHP=/path/to/php python3 scripts/test-stripe-webhook.py` runs `php -S` on a temp copy of `toolkits/` plus a fake SMTP server, and posts signed sample events. The HMAC is computed in Python, independently of the PHP. It covers the signature (wrong secret, stale timestamp, malformed header, tampered body, secret rotation), brand/type/unpaid filtering, SKU mapping by Payment Link ID and by metadata, the email bodies, idempotency, SMTP failure then retry, GET → 405, and the thank-you page (2 links, 34 for the bundle, fallback). It writes the sample buyer email to `scripts/.webhook-test-sample-email.txt` (gitignored).

Never commit paid PDFs, zips or .ics files, the webhook config or its data (`.gitignore` blocks them).
