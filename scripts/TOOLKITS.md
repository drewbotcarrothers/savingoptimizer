# Paid toolkits on savingoptimizer.com

Generated by `python3 scripts/build-toolkits.py` (idempotent; re-run after any config change).

| Path | What | Indexed |
|---|---|---|
| `/toolkits/` (`toolkits/index.html`) | Hub of all 16 toolkits | yes, in sitemap |
| `/toolkits/<slug>.html` | One sales page per toolkit, priced CTA "Buy, CA$15" → Stripe Payment Link, no ad code | yes, in sitemap |
| `/toolkits/thank-you.php?sku=<slug>` | Download page after Stripe checkout | **noindex, nofollow** (meta + X-Robots-Tag), not in sitemap |

## Config (`scripts/toolkits-config.json`)
- `payment_links`: one live Stripe Payment Link per slug (created 2026-11-11; product metadata `brand=savingoptimizer`, `sku=<slug>`; CA$15.00 one-time). Don't merge until the 32 buyer download URLs are set on the host and Drive sharing is Anyone with the link · Viewer.
- `bundles`: one bundle, `bundle-all` (all 16 for CA$39, live Stripe link). Shown as a panel at the top of `/toolkits/` and as a secondary "Get all 16 for CA$39" button on every sales page. `thank-you.php?sku=bundle-all` shows the bundle zip (`PUBLIC_TOOLKIT_BUNDLE_ALL_FOLDER_URL` / `_ZIP_URL`) and then each toolkit's own folder and zip.
- `hubs` / `top_posts`: where the priced CTA box goes (top posts = top 2 per toolkit from GSC 2026-08-01..11-03, clicks then impressions). UTMs: `utm_source=savingoptimizer&utm_medium=site&utm_campaign=toolkit&utm_content=hub-<hub>|post-<slug>`.
- `lead_magnet`: provider **Hostinger Reach** (the same provider latestmortgagerates.ca uses, as an embedded form). The sign-up block renders **hidden**, and the Reach script isn't emitted, until `reach_form_id` **and** `sender_mailing_address` (CASL) are both set. Set up in Reach first: verify savingoptimizer.com as a sending domain, turn on double opt-in, create an embedded form with email, optional first name and an **unticked** consent checkbox using the wording in `build-toolkits.py` (`signup()`), then add a welcome automation that sends the free sample. `privacy.html` switches to its newsletter wording automatically when the block is ready (the `tk-privacy:*` markers). If the site ever sends a Content-Security-Policy, allow `cdn-reach.hostinger.com`, `reach-forms.hostingerusercontent.com` and `reach.hostinger.com` (see the latestmortgagerates `.htaccess`).

## Buyer download links (not in git)
The thank-you page reads, per slug (upper-case, `-` → `_`):
`PUBLIC_TOOLKIT_<SLUG>_FOLDER_URL` and `PUBLIC_TOOLKIT_<SLUG>_ZIP_URL` (must start with `https://`).

This is a no-build static site deployed by Hostinger Git sync, so there are no GitHub Actions build variables. Set the 34 values (16 toolkits plus the bundle, folder and zip each) either:
1. as server environment variables (e.g. `SetEnv PUBLIC_TOOLKIT_PETS_FOLDER_URL "https://…"` in an **untracked** `.htaccess` inside `public_html/toolkits/`, if the host allows), or
2. in `/home/<user>/.so-toolkit-links.ini` — one level **above** `public_html`, never in the repo — with quoted values:
   ```ini
   PUBLIC_TOOLKIT_PETS_FOLDER_URL = "https://drive.google.com/drive/folders/…"
   PUBLIC_TOOLKIT_PETS_ZIP_URL = "https://drive.google.com/uc?export=download&id=…"
   ```
If a link is missing, the page tells the buyer the link is coming by email (fallback: send it manually within 24 h).

## Stripe Payment Link "After payment"
Redirect to `https://savingoptimizer.com/toolkits/thank-you.php?sku=<slug>&session_id={CHECKOUT_SESSION_ID}`.

Never commit paid PDFs, zips or .ics files (`.gitignore` blocks them).
